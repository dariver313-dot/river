# 澳门娱乐城日结报表

本地运行的日结报表工具。浏览器只与本机服务通信，订单数据仅经 `auth-service` 的只读日报接口获取；不会调用加款接口，也不会把 API Key 发送给浏览器。

## 工作方式

报表引擎分为两层：

- **通用核心**：按北京时间查询成功充值、成功提款；按平台返回的渠道名称匹配模板渠道；逐笔计算费率与固定手续费；发现未匹配或重复匹配时阻止导出。
- **模板适配器**：识别模板的 `总汇` 与 `后台` 公式关系，自动定位每个渠道的账本输入行、汇总公式和余额衔接位置。日常不需要配置单元格坐标。

当前已内置“2026澳门娱乐城”模板适配器。新增不同结构的模板时，应新增适配器，而不是让使用者手填 Excel 坐标；这是通用能力与可审计性之间更可靠的边界。

## 首次运行

1. 将 `.env.example` 复制为 `.env`，填写 `AUTH_SERVICE_URL` 与只读 `AUTH_API_KEY`。
2. 将模板放在 `templates` 目录。当前目录已包含 `2026澳门娱乐城.xlsx`。
3. 执行 `npm install`，再执行 `npm start`。
4. 打开 `http://127.0.0.1:3210`。在“渠道与费率”中确认平台渠道名称、代收/代付费率、固定每笔费用及备注。

## 日常使用

1. 选择报表日期；需要衔接余额时上传上一日已完成报表。
2. 对没有上游订单接口的数据，在“补录”中填写未提交、人工充值、资金转出和备注。
3. 查询并核对。渠道名称未匹配、同一名称匹配到多个渠道、模板输入位含公式或账本行已满时，系统会阻止导出。
4. 导出 Excel。模板原有样式、工作表和汇总公式保持不变；首次需要使用的空白渠道块若缺少标准汇总公式，会按同模板规则补齐该块公式。

## 数据接口

- `POST /api/platform-b/report/rechargeOrders`：按北京时间自然日读取会员类型 `2`、`3` 的全部成功充值订单，固定上游条件 `orderType=0`、`timeType=0`、`status=0000`。
- `POST /api/platform-b/report/withdrawOrders`：按北京时间自然日读取会员类型 `2`、`3` 的全部成功提款订单，固定上游条件 `timeType=0`、`status=8`。

`auth-service` 分页拉全、校验总数、按订单号去重并只返回报表需要的字段。任一页不完整时接口会失败，不会产出部分日报。

## 本地文件

- `data/report-config.json`：渠道名称、费率、备注等业务配置。
- `outputs`：已导出的报表副本。
- `templates`：可选模板文件。
