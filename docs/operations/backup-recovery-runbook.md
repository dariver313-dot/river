# djmima D1 备份与恢复运行手册

## 目标与边界

- **RPO：24 小时；RTO：4 小时。** 生产 D1 数据库必须启用至少每日一次的受控备份，并保留最近 30 份日备份与 12 份月备份。
- 备份保存的是 D1 的加密记录和审计记录，**不应改用应用导出的明文 JSON 作为数据库备份**。
- `VAULT_ENCRYPTION_KEYS`（或兼容期内的 `VAULT_ENCRYPTION_KEY`）与审计签名密钥必须存在独立、受控、可恢复的密钥托管中；密钥和数据库备份不能放在同一普通共享目录。

## 每日检查

1. 在 D1 的受控管理面确认最近备份成功时间不早于 24 小时，并记录备份标识、时间、操作者与保留期。
2. 检查 Sites 生产环境仍有 `PRIMARY_ADMIN_EMAIL`、加密密钥和审计签名密钥；只记录“已配置”，不要导出或截图密钥值。
3. 如备份失败，停止密钥轮换和批量删除，并在当天修复后补做一次恢复演练。

## 月度恢复演练

1. 选择最近一次成功备份，建立**隔离的非生产 D1**；不得覆盖生产数据库。
2. 将备份恢复到隔离数据库，并只在隔离环境注入与该备份匹配的历史加密密钥、审计签名密钥。
3. 在隔离、非公开的站点版本中，用测试管理员验证：项目数量、个人/公共访问边界、至少一条密码解密、TOTP 配置读取、审计签名状态和双人导出流程。
4. 记录恢复开始/结束时间、备份标识、验证项目、结果和异常；验证完成后销毁隔离环境或撤销访问授权。
5. 任何一次解密失败都视为恢复失败：保留现场，恢复对应历史密钥，禁止在生产替换现有密钥。

## 生产事故恢复

1. 先将站点访问范围缩为管理员，暂停会改变数据的操作。
2. 选择最近满足 RPO 的备份，在新建隔离 D1 中先完成恢复验证；不要直接覆盖生产。
3. 用同一套密钥验证成功后，按受控变更流程切换 D1 绑定或恢复生产数据。
4. 恢复后检查审计链完整性、应用管理员、公共密码库映射、最近导出请求和抽样解密；将事件、影响范围和补救措施写入运维记录。

## 禁止事项

- 不把明文导出文件、密钥值、二维码或 TOTP Setup Key 写入工单、截图、仓库或恢复记录。
- 不在未完成隔离演练前执行生产覆盖恢复。
- 不在无法读取历史项目时删除旧密钥。
